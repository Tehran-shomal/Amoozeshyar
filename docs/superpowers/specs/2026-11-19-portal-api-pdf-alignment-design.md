# طرح اتصال API پورتال و تطبیق با PDF

> وضعیت: این طرح تاریخی است و بخش‌های مربوط به ثابت‌ماندن fixtureهای نمونه و وصل‌کردن کد/گروه PDF به آن‌ها با پیاده‌سازی data-driven و سیاست «دادهٔ واقعی یا اعلام محدودیت» جایگزین شده‌اند. برای وضعیت فعلی به `docs/superpowers/specs/2076-05-07-full-system-reconstruction.md`, `docs/PDF_PAGE_MAPPING.md` و `docs/screens/selected-courses.md` رجوع کنید؛ این سند منبع قرارداد جاری نیست.

## هدف

اتصال فرانت موجود به APIهای فعلی Django و بررسی تطبیق بصری آن با `Amoozeshyar.pdf`، بدون بازنویسی متن‌ها، داده‌های نمونه یا چیدمان مرجع PDF.

## راهکار انتخاب‌شده

از APIهای same-origin و نشست Django استفاده می‌کنیم. فرانت ابتدا CSRF را می‌گیرد، سپس ورود را انجام می‌دهد و برای درخواست‌های تغییردهنده هدر `X-CSRFToken` می‌فرستد. وضعیت نشست با `/api/accounts/me/` بررسی و خروج با `/api/accounts/logout/` انجام می‌شود.

در جریان درس، `/api/scheduling/active-term/` و `/api/scheduling/offerings/` فقط برای پیدا کردن شناسهٔ ارائهٔ متناظر با کد درس و گروه PDF خوانده می‌شوند؛ متن و مقدارهای قابل‌مشاهدهٔ PDF از fixtureهای فعلی می‌مانند. دکمهٔ افزودن فقط وقتی درخواست ثبت‌نام می‌فرستد که ارائهٔ متناظر به‌طور یکتا پیدا شده باشد. خطاهای API در همان صفحه و بدون جایگزین‌کردن داده‌های PDF نشان داده می‌شوند.

## مرزهای API و محدودیت‌ها

- API فهرست ثبت‌نام‌های قبلی دانشجو را ندارد؛ بنابراین ردیف‌های نمونهٔ حذف درس شناسهٔ معتبر ندارند و حذف واقعی آن‌ها به API فعلی قابل اتصال نیست. آن دکمه‌ها تا زمان ارائهٔ شناسهٔ معتبر نباید درخواست حذف بفرستند.
- ثبت‌نام واقعی به نشست دانشجو، پروفایل Student، ترم/ارائهٔ فعال و قواعد backend وابسته است. APIها و داده‌های موردنیاز برای شهریه، نمره و سایر صفحات PDF موجود نیستند؛ آن صفحات نمونه باقی می‌مانند.
- پایگاه دادهٔ محلی migrationهای `core.0004` و `core.0005` را اجرا نکرده است. `0004` تبدیل timestampهای قدیمی را انجام می‌دهد و منطقهٔ زمانی مبدأ داده‌ها نامشخص است؛ در این کار migration یا seed روی DB محلی اجرا نمی‌شود.

## تطبیق با PDF

PDF مرجع ۹۶ صفحه دارد و UI فعلی ۳۴ مسیر/حالت اصلی دارد. بررسی قبلی اختلاف تصویری مودال‌های PDF را نشان داده است: PDF مودال را به‌صورت پنجرهٔ مستقل روی پس‌زمینهٔ خاکستری نشان می‌دهد، اما UI فعلی پوستهٔ پورتال را زیر لایهٔ تیره نگه می‌دارد. پس از تأیید این طرح، مسیرها و حالت‌های قابل‌مقایسه با صفحات PDF بازبینی می‌شوند و فقط تفاوت‌های لازم برای تطبیق با همان مرجع اصلاح خواهند شد. داده و متن مرجع تغییر نمی‌کند.

## اعتبارسنجی

- بررسی دستیِ ورود، حفظ نشست، `/me/`، خروج، خواندن offering، ثبت‌نام موفق/ردشده، و نبود درخواست حذف برای ردیف فاقد شناسه.
- مقایسهٔ screenshotهای مسیرها و حالت‌های PDF با screenshotهای فرانت در viewport و مقیاس یکسان؛ گزارش هر صفحه/حالت که تطبیق کامل ندارد. ادعای «۱۰۰٪» فقط برای صفحه‌ها و حالت‌هایی مطرح می‌شود که واقعاً مقایسه و تأیید شده‌اند.
- اجرای بررسی‌های Django پس از پیاده‌سازی. آزمون API تغییردهنده روی DB واقعی محلی تا تعیین تکلیف migration منطقهٔ زمانی انجام نمی‌شود.

## موارد خارج از محدوده

ساخت endpoint جدید، migration یا seed داده، حذف یا بازنویسی fixtureها، تغییر متن و محتوای PDF، و اتصال صفحاتی که API پشتیبان ندارند.
