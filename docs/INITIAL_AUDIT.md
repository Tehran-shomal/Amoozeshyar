## وضعیت فنی موجود

- Django monolith با Django `5.2.18`، Python `3.12` برای اجراهای این ممیزی، SQLite توسعه و JavaScript بدون framework.
- ۱۸ اپ دامنه ثبت شده‌اند. مدل‌ها در `apps/core/models.py` متمرکزند و admin در `apps/core/admin.py` ثبت می‌شود؛ موجودی ۴۳ مدل در `PROJECT_STRUCTURE.md` آمده است.
- پنج گروه فرانت‌اند موجودند: Mobina، Shaghayegh، Academic Services (Omid/Shahsavand)، Parsa و Neyousha/Pouya.
- registry شامل ۳۲ slug صفحهٔ پرتال است؛ علاوه بر آن ورود، داشبورد، انتخاب نیمسال و گروه‌های منو اجزای مشترک‌اند.
- APIهای قابل استفاده: حساب/CSRF و نشست، نیمسال/ارائه‌ها، ثبت‌نام/حذف درس، بازبینی درخواست‌های موجود و API عمومی محتوای صفحهٔ پرتال. همهٔ صفحه‌های دامنه از API هم‌مبدأ صفحه داده می‌گیرند؛ فرم‌ها با Django forms اعتبارسنجی و ذخیره می‌شوند.
- ۱۴ namespace دامنه URL اختصاصی ندارند: attendance، grading، counseling، classroom، tuition، tickets، student_services، thesis، scholarships، people، reports، online_exam، internship و notifications. بعضی داده‌های این حوزه‌ها از API عمومی صفحه یا selectorها خوانده می‌شوند؛ این را نباید با API دامنه‌ای مستقل اشتباه گرفت.
- API پرداخت واقعی، درگاه مالی، صدور رسمی کارت/مدرک، queue/background worker و provider بیرونی در این checkout پیکربندی نشده‌اند.

## PDF و تطبیق دیداری

- فایل مرجع `Amoozeshyar.pdf` دارای ۹۶ صفحه است. تصاویر مرجعِ قبلاً رندرشده برای صفحات ۰۱ تا ۹۶ در پوشهٔ موقت یافت شد و هر ۹۶ صفحه در هشت contact sheet مرور شد.
- صفحات شامل ورود و داشبورد، گروه‌های منو، صفحات آموزشی/مالی/درخواست، نتیجه‌های عملیات، انتخاب درس و مودال‌های تأیید هستند. نقشهٔ قبلی در `docs/portal-pdf-comparison.md` توضیح می‌دهد کدام حالت‌ها پیاده، بازبینی‌شده یا بازنمایی‌نشده‌اند.
- سند تطبیق موجود ۵۸ حالت رابط را گزارش می‌کند، در حالی که پوشهٔ موقت ۷۵ فایل screenshot دارد؛ شمارش‌ها ظاهراً یک تعریف واحد ندارند و باید در نقشهٔ جدید تفکیک شوند.
- این نوبت همهٔ تصاویر مرجع را دید، اما screenshot تازه از branch فعلی در هفت viewport درخواستی گرفته نشده؛ بنابراین تطبیق نهایی یا ادعای «۱۰۰٪ منطبق» ثبت نمی‌شود.
- متن استخراج مستقیم PDF برای خواندن محتوای فارسی قابل اتکا نبود؛ تصویر مرجع مبنای نگاشت دیداری است. صفحات مستقلِ نتیجه/مودال که route و رفتار backend ندارند، در وضعیت بازنمایی‌نشده باقی می‌مانند.

## رفتار و داده

- ورود با session Django، CSRF، قفل پس از پنج تلاش ناموفق برای ۹۰۰ ثانیه و نقش‌های فعال انجام می‌شود. رمز `Person` با password hasher بررسی می‌شود؛ `UserAccount.password` منبع احراز هویت نیست.
- عملیات انتخاب/حذف درس در service تراکنشی و با مالکیت Student انجام می‌شود؛ قواعد prerequisite، ظرفیت، بدهی، پنجرهٔ زمانی، تداخل و سقف واحد تست دارند. بعضی مقادیر (نمرهٔ قبولی ۱۰/۲۰ و تداخل امتحان در زمان دقیق) در ADR به‌عنوان فرض ثبت شده‌اند، نه مرجع قطعی.
- فرم‌های صفحه مالک و وضعیت اولیه را از سمت سرور تعیین می‌کنند. دادهٔ مالی و آموزشی از پروندهٔ انتخابی فیلتر می‌شود.
- فایل رفتاری `نیازمندی_های_آموزشیار.md` که SSOT معرفی کرده در checkout وجود ندارد؛ ۱۵۲ شناسهٔ SDD به‌تنهایی متن رفتار و مجوزها را تعیین نمی‌کنند. از روی شناسه‌ها به‌تنهایی مدل یا قاعدهٔ جدید ساخته نمی‌شود.
