# فرم ارزشیابی استاد

- مالک/route: Miri؛ `/portal/evaluation-form/`؛ قالب اختصاصی `miri/evaluation_form.html`؛ از ردیف درس در `/portal/evaluation/` باز می‌شود.
- مرجع: [PDF صفحهٔ ۱۷](page-17-reference.png)؛ صفحات ۳۱ تا ۳۳ همین فرم را برای سه Enrollment متفاوت نشان می‌دهند و صفحهٔ ۴۹ crop مقیاس پاسخ است.
- ظاهر/رفتار: اطلاعات واقعی درس، استاد و نیمسال؛ امتیاز کلی اجباری و دو فیلد اختیاری موجود (`teaching_quality`, `behavior`) با گزینه‌های رادیویی ۱ تا ۵؛ نظر اختیاری؛ ثبت نهایی؛ پس از ثبت، فرم read-only است.
- داده: `TeacherSurvey` و Enrollment فعال همان Student/Term. فقط ستون‌های موجود استفاده می‌شوند؛ پنج معیار مستقل PDF در schema فعلی وجود ندارند و این اختلاف پنهان/ذخیره‌سازی‌شده فرض نمی‌شود.
- API: `GET|POST /api/portal/pages/evaluation-form/`; body شامل `enrollment`, پنج فیلد `*_rating` و `comment` است. شناسهٔ enrollment باید به پرونده و نیمسال جاری تعلق داشته و فعال باشد؛ دسترسی به رکورد دیگران `404` می‌دهد؛ rating خارج از ۱ تا ۵ پذیرفته نیست؛ duplicate در فرم و تراکنش دوباره بررسی می‌شود.
- stateها: اگر چند درس واجدشرایط باشد انتخاب درس نشان داده می‌شود؛ یک درس به‌طور خودکار باز می‌شود؛ پاسخ قبلی قابل ویرایش نیست. امتیازهای قبلی همان‌طور که ذخیره شده‌اند نمایش داده می‌شوند.
- محدودیت تطبیق: مدل `CourseOffering` کد گروه کلاس را نگه نمی‌دارد؛ کد گروه نمونهٔ PDF جعل نشده است. crop صفحهٔ ۴۹ پنج انتخاب متفاوت ۱،۲،۳،۴،۵ را نشان می‌دهد؛ پاسخ‌های مرجع به فرم خالی پیش‌فرض نشده‌اند. فقط فیلدهای موجود `TeacherSurvey` از API ذخیره می‌شوند؛ پنج rating مستقل PDF هنوز در schema نیستند و regressionهای تازه اجرا نشده‌اند. داده‌های محلی ممکن است تعداد درس/استادهای نمونه را نداشته باشند.
- ایمنی داده: migration ساخته شد ولی روی SQLite محلی اجرا نشده؛ هیچ رکوردی seed/ویرایش/حذف نشده است.
- راستی‌آزمایی: regressionهای فرم/API به `apps/core/test_frontend.py` افزوده شده‌اند اما به درخواست کاربر اجرا نشده‌اند؛ capture جاری احرازشده موجود نیست. `manage.py check` و بارگذاری template پس از تغییر، مرحلهٔ بعدی verification است.
